# Construction Materials ERP

ERP for a construction-materials supplier (TMT bars, pipes, cement, binding wire, angles and
channels; two shops and a godown): purchase with landed cost, stock, GST billing, credit,
e-way bills, daily closing. Single client now, multi-tenant SaaS later.

**Read before any task:** `docs/SPEC.md` (business rules B1–B18, gap fixes G1–G27, data model),
`docs/ROADMAP.md` (milestones and status). Open questions: `docs/GAP_ANALYSIS.md`.
Use `/milestone <n>` to build one milestone.

## Stack

- Backend: Python 3.13, FastAPI, SQLAlchemy 2 (sync, psycopg 3), Alembic, PostgreSQL 17, uv,
  pytest, ruff, mypy (strict).
- Frontend: React 19 + TypeScript (strict), Vite, React Router, TanStack Query, CSS Modules with
  tokens, Vitest + Testing Library, ESLint, Prettier.
- Docker Compose for dev and simple production; GitHub Actions CI.

## Layout

```text
backend/app/api/v1/    routes (thin) + role checks       backend/app/domain/   pure business rules
backend/app/services/  use cases, one transaction each    backend/app/models/   tables
backend/app/core/      config, db, security, errors      backend/tests/{unit,integration}
frontend/src/          pages/, components/, api/, auth/, styles/tokens.css, modules.ts
docs/                  SPEC, ROADMAP, GAP_ANALYSIS, ARCHITECTURE, API, DESIGN, adr/
```

## Hard rules

- Money and quantities are `Decimal`/`NUMERIC`. Never float, in Python or in stored data.
- Business maths goes in `backend/app/domain/` with unit tests written first. No DB, HTTP or
  clock there (pass `today` in).
- Every table has `tenant_id` (use `TENANT_ID` from `app/core/tenancy.py`). No tenant logic yet.
- Stock and balances are derived from append-only ledgers. Issued documents are never deleted
  or edited in place; use credit/debit notes. Numbers come from `services/numbering.py` inside
  the saving transaction.
- New business tables inherit `Audited`, `TenantMixin`, `TimestampMixin`, `ActorMixin`.
- Cost, margin and profit never reach non-owner roles: separate response models chosen by
  `principal.sees_cost`; test as a counter user.
- Schema changes only through Alembic migrations; review autogenerated files (enum CHECK
  constraints get duplicated by autogenerate: keep only the `sa.Enum(..., create_constraint=True)`).
- Every bill is a real GST tax invoice. Never build hidden, dummy or unaccounted billing modes
  (ADR 0005). Test data lives only in dev/staging, watermarked TEST.
- UI: follow `docs/DESIGN.md`; use the `frontend-design` and `ui-ux-pro-max` skills
  (`.claude/skills/README.md`). Keyboard first, tabular numbers, tokens only, no raw hex.
- If the spec is unclear or a rule is marked Owner/Accountant in GAP_ANALYSIS, ask; don't guess.

## Commands

```bash
make up / make down / make logs        # dev stack: web :5173, API :8000, db :5432
make seed                              # owner / owner-pass-123 (dev only)
make test                              # backend + frontend tests
make lint                              # ruff, mypy, alembic check, eslint, tsc, prettier
make migration m="add item master"     # then review the file, then make migrate
```

Without Docker: `cd backend && uv sync && uv run pytest tests/unit` (unit tests need no DB);
`cd frontend && npm install && npm test`.

## Workflow

One milestone per session and per branch/PR. Tests and lint green before finishing. Update
`docs/ROADMAP.md` status and `docs/SPEC.md` in the same change. Conventional commits
(`feat(m4): ...`).
